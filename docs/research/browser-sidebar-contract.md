# Browser sidebar bridge contract (backend implemented)

`sidebar.bindingForAgent({agentId})` → `null | {bindingId,targetId,cdpSessionName,state,url,title,contextRevision}`. `cdpSessionName = "sidebar:" + bindingId`; state `active|closed|revoked|unavailable`. Unavailable CDP fails closed but is retryable. CDP process change durably revokes. Function is now live and refreshes URL/title from CDP before returning; revision increments on changed page context.

First-party backend: `src/sidebar/`; extension: root `browser-extension/`. Trusted-local-user prototype, NOT an agent/tool sandbox. Existing UI remains `/agent/:id?presentation=sidebar` and uses ordinary Hyper session authentication (bridge bearer is never accepted for UI, REPL, RPC or arbitrary agents).

Default base: `http://localhost:3010` (use actual configured Hyper port). All `/sidebar/api/*` calls require `Origin: chrome-extension://<32 a-p chars>` and literal loopback HTTP host. No forwarded-host trust. JSON POSTs only, except OPTIONS. CORS reflects a validated extension origin. Never put bearer secrets in URLs.

- `POST /sidebar/api/pair` `{}` → `{pairId, token, approvalUrl, expiresAt}`. Store token in extension-local storage; it is pending until user approval. Open approvalUrl in an ordinary Hyper tab. Pair ID is a non-secret identifier. UI shows extension ID and explicit Approve button, protected by existing Hyper session and same-origin POST. Pair expires after 10 minutes.
- `POST /sidebar/api/status` bearer → `{approved, revoked}` (pending token permitted).
- `POST /sidebar/api/bind` bearer + `{browserEpoch, tabId, targetId, url?, title?}` → `{agentId: string|null, frameUrl, bindingId, targetId}`. browserEpoch is a random UUID stored in chrome.storage.session (new on browser restart); tabId positive integer; targetId exact chrome.debugger.getTargets().id. Server validates target against local CDP, never URL matching. Repeated binding key returns the same binding. New bindings have **no agent**; `frameUrl` is `/sidebar/draft/:bindingId?presentation=sidebar`. Existing agents retain `/agent/:id?presentation=sidebar`. Bind, context, and draft GET never create or start agents.
- `POST /sidebar/api/context` bearer + `{browserEpoch, tabId, targetId, url?, title?}` → same binding response. Existing binding required; target replacement rejected; refreshes context only. URL/title come from the validated CDP target (optional extension hints are ignored). Page strings are untrusted data.
- `POST /sidebar/api/close` bearer + `{browserEpoch, tabId}` → `{closed:true}`. Durable tombstone; binding cannot be resurrected. Chat persists. Close is idempotent.
- `POST /sidebar/api/revoke` bearer + `{}` → `{revoked:true}`. Revokes credential and every binding. Pending, expired and already-revoked credentials may revoke idempotently; token hash and exact Origin must still match.

Errors JSON `{error:string}` with 400/401/403/404/409/413/429/502. Active tokens expire after 30 days. Bearer credentials are stored hashed. Binding identity includes pairing identity + browserEpoch + tabId, unique in Postgres. Backend stores context separately, never as fake messages. Server restart retains pairings/mappings; extension reload may reset browserEpoch and create a safe new draft. browserEpoch is NOT CDP process identity: server stores the /json/version browser websocket ID and revokes on change.

`GET|POST /sidebar/draft/:bindingId` is a separate **owner-session UI** endpoint, never bearer-authorized. It requires a loopback peer/host, rejects forwarded headers and Authorization, and requires an active binding under an approved unexpired pair. POST additionally requires exact same-origin Origin even without a configured password. GET renders the shared Hyper composer and normal shell, with tab title and current default model, without a placeholder agent. The first nonempty submit (text or attachments) atomically claims `first_send_state`, fetches current CDP title and `settings.modelDefault`, creates once, persists `agent_id` before the normal message/enqueue pipeline, then redirects to the ordinary per-tab chat. The binding ID is the durable one-shot idempotency key: concurrent POSTs wait and redirect; completed retries never append again. Different submissions from stale draft frames are also deduplicated; send subsequent messages in the redirected chat.

Interrupted first submits fail closed: no expiring creation lease, automatic replay, or duplicate agent creation after crashes. A crash before mapping may leave an orphan agent and stuck `sending` binding requiring inspection; a failure after mapping allows reopening the existing chat to inspect/retry manually. This is at-most-once creation/first-submit attempt, not transactional exactly-once completion across crashes. iframe login/cookie policy still requires live Chrome verification.
